# Broker Call

Голосовой тренажёр звонка фрахт-брокеру. Студент говорит в микрофон по-английски,
брокер отвечает голосом, лезет в систему за данными и торгуется. За весь
разговор нажимать нечего.

Живёт на https://dispatch4you.com/broker-call/. Старая страница
`pages/ai-broker-chat.html` пока работает как работала — её снимут, когда новая
версия отстоится.

## Запуск

```bash
cd broker-call
npm install
cp .env.example .env.local     # подставить ключи
npm run dev                    # http://localhost:5180
```

Без ключей приложение откроется, но разговор не начнётся — эндпоинты честно
ответят «нет ключа». Для живого разговора нужен `GEMINI_API_KEY`; для запасного
пути — `GROQ_API_KEY` (распознавание и озвучка). `CEREBRAS_API_KEY`
необязателен: без него диалог идёт через Groq.

```bash
npm test        # 162 теста: торг, автомат звонка, набор звонка, оценка, границы речи, протокол Gemini, ручки сервера
npm run build   # сборка в dist/ + пересборка api/broker-config.php
```

Если что-то не работает — **http://localhost:5180/api/health**. Это живые пробы,
а не догадки: короткий настоящий запрос к каждому сервису тем же путём, каким
идёт звонок, и текст отказа провайдера как есть. На боевом сайте та же ручка
лежит по адресу
<https://dispatch4you.com/api/broker-call.php?action=health> и отвечает в
точности той же формой.

## Как это работает

```
микрофон открыт весь звонок
   │
   ├── детектор границ речи ──── человек заговорил ──> брокер замолкает
   │                                                    (перебивание)
   └── фраза закончилась
          │
          ▼
      распознавание (Groq Whisper)
          │
          ▼
      модель ──── вызывает инструмент ──> CallMachine ──> карточка в ленте
          │            (проверить MC, открыть груз,        + музыка ожидания
          │             посчитать ставку)                    на линии
          ▼
      озвучка (Groq Orpheus) ──> телефонный фильтр 300–3400 Гц
          │
          ▼
      слова проявляются на экране в такт голосу
```

Это запасной путь. Когда на сервере есть ключ Gemini, все четыре шага
схлопываются в один поток по вебсокету — микрофон уходит непрерывно, голос
приходит непрерывно, паузы режет провайдер. Инструменты и CallMachine при этом
те же самые: меняется только дорога, по которой ходит звук.

### Ноль нажатий

Единственное касание — «Позвонить». Убрать его нельзя: браузеры (особенно Safari
на iOS) не отдают микрофон и не разрешают воспроизведение звука без жеста
пользователя. Зато оно честно притворяется тем, чем и является, — набором
номера. **Звонит диспетчер.** Входящих в его сторону в тренажёре не бывает:
брокер владеет грузом, диспетчер владеет траком, и это тот, кто ищет груз,
снимает трубку первым.

Дальше кнопок нет. Когда фраза закончилась, решает детектор, а не таймер: он
подстраивается под уровень шума в комнате и прощает паузу внутри фразы (700 мс),
поэтому не режет человека на середине задумчивости. Заговорил поверх брокера —
тот замолкает, и в стенограмме остаётся ровно та часть его реплики, что успела
прозвучать.

### Каждый звонок новый

Сценариев нет. Звонок собирает `src/call/makeCall.ts`: имя, компания, характер и
голос брокера, маршрут, груз, вес, окна погрузки, ставка с борда и потолок — всё
своё на каждый звонок. Раньше здесь лежали восемь сценариев, записанных руками,
и один и тот же сценарий давал один и тот же разговор: тот же брокер, те же
цифры, тот же поток случайных чисел — сид равнялся id сценария.

Генератор детерминированный: сид разворачивается в тот же звонок и в браузере, и
на сервере. Это важно, потому что промпт собирается на сервере, а инструменты
исполняются в браузере: разъедься они, брокер говорил бы про один груз, а
система считала другой.

Список сидов — `src/call/seeds.ts`, шестьдесят штук. Он существует не для
ограничения, а ради боевого сервера: PHP не умеет исполнять наш генератор,
поэтому все шестьдесят промптов собираются при сборке в `api/broker-config.php`.
Второй реализации, которая разъедется с первой, не заводится. Нужно больше
разнообразия — дописать строки в `seeds.ts`, остальное сгенерируется само.

Первая реплика брокера тоже не задана. Он снимает трубку своими словами: раньше
строка навязывалась дословно (`Answer the phone with exactly this line`), и все
звонки начинались одинаково.

Порядок вопросов не диктуется. Он сидел не в промпте, а в результатах
инструментов — «проверил MC → теперь спроси оборудование → теперь дай детали
груза». Инструмент возвращает факты и границы; что спрашивать дальше, решает
модель. Приказом осталось только то, что нарушать нельзя: отказ перевозчику,
потолок ставки, жёсткое окно погрузки.

### Факты отдельно от текста

Состояние звонка (`src/call/CallMachine.ts`) меняется **только** вызовами
инструментов. Никакого разбора транскрипта регулярками: в прежней версии
`locationAnswered` срабатывал на слово «ready» в любом контексте, а
`bookingDone` — на слово «george».

Потолок ставки лежит в коде (`src/call/guards.ts`), а не в тексте промпта.
Раньше это была фраза «your absolute max is $2,150», и модель переступала её
под нажимом. Теперь `propose_rate` возвращает решение, а не мнение, — и тест
`«никогда не даёт больше потолка»` гоняет десять раундов торга, проверяя это.

### Ключи и промпт не уезжают в браузер

Ключи читает только дев-сервер (`server/devProxy.ts`) из `.env.local`.
Системный промпт (`src/call/prompt.ts`) и схемы инструментов
(`src/call/toolSchemas.ts`) импортирует тоже только он, поэтому в бандл фронта
они не попадают:

```bash
npm run build
grep -c "You are a person on a phone call" dist/assets/*.js   # 0
grep -cE "gsk_|csk-|sk-proj" dist/assets/*.js                 # 0
```

Данные грузов, включая `maxRate`, в бандле есть — они нужны на клиенте для
исполнения инструментов и подсчёта оценки. Для тренажёра это приемлемо:
подглядеть в потолок ставки студент может только обманув сам себя.

Контракт эндпоинтов (`/api/config`, `/api/turn`, `/api/stt`, `/api/tts`,
`/api/debrief`, `/api/realtime-session`, `/api/gemini-session`) специально
простой — на боевом сайте его один в один повторяет `api/broker-call.php`, и
фронт не меняется ни строкой.

### Три транспорта

| | Пайплайн | Gemini Live | Realtime |
|---|---|---|---|
| Стоимость | бесплатно | бесплатно (Live API) | ~$0.06–0.10 за минуту |
| Задержка | 800–1500 мс | 300–800 мс | 300–800 мс |
| Сетевых походов на реплику | 4 | 0 (поток) | 0 (поток) |
| Перебивание | своё, на детекторе | встроенное | встроенное (semantic VAD) |
| Ключ | Groq / Cerebras | Gemini | OpenAI |

Все три реализуют один интерфейс `VoiceTransport`, поэтому экран звонка не
знает, какой работает. Решает сервер: из клиента ни платный, ни новый режим не
включить, даже подменив запрос.

Порядок попыток строит `buildCandidates` в `src/store/useCallStore.ts`: сначала
Gemini (если на сервере есть ключ), затем Realtime (если включён явно), и
пайплайн последним всегда. Если предпочтительный транспорт не поднялся, он тихо
сворачивается — без сигнала «занято» — и звонок идёт следующим. Причина уходит
в консоль; живое состояние провайдера всегда видно в `?action=health`.

Отказ в микрофоне откат не запускает: второй транспорт спросил бы разрешение
ещё раз и получил тот же отказ.

**Про Gemini.** Имя модели в коде не написано ни разу. Сервер спрашивает
`models.list` в момент запуска и выбирает по политике из
`src/call/geminiModels.ts`: разговор — только модели с `bidiGenerateContent`,
предпочтительно native audio (нет суточного лимита); разбор — flash-lite
(500 запросов в сутки против 20 у pro). Политика покрыта тестами и выгружается
в `api/broker-config.php`, чтобы боевой PHP выбирал так же. Вписанное в код имя
модели — то, на чём тренажёр замолкал трижды.

Ключ в браузер не уезжает: `/api/gemini-session` выдаёт одноразовый номер сессии
и запирает вместе с ним системный промпт, голос и список инструментов, поэтому
клиент шлёт пустой `setup` и подменить ничего не может.

**Вебсокет идёт через сервер, а не напрямую к Google.** Задумано было иначе:
сервер выпускал эфемерный токен Google (`v1alpha/auth_tokens`), браузер шёл с ним
прямо к провайдеру. Токен выпускается, но сокет его не принимает ни в каком
виде: как `?access_token=` Google не распознаёт его вовсе (`1008 unregistered
callers`), как `?key=` считает невалидным (`1007`). Проверено на живом ключе, оба
параметра, с префиксом `auth_tokens/` и без; прямой ключ при этом работает и на
v1alpha, и на v1beta. Похоже, эфемерные токены недоступны на бесплатном ключе.
Поэтому дев-сервер поднимает сокет сам и пропускает трафик через себя — ключ
остаётся на сервере, как и задумывалось.

Из этого следует ограничение: **на боевом сайте Gemini этим путём не заработает**
— PHP на Hostinger вебсокет проксировать не умеет. Локально звонок живой, на
`dispatch4you.com` пока остаётся прежний путь.

### Оценка

Баллы считает `src/call/scoring.ts` по фактам звонка — одинаковый разговор
всегда даёт одинаковый результат. Модель пишет человеческий разбор поверх уже
посчитанных чисел и не может переврать сумму или похвалить за несделанное.
Метрики общие: открытие, квалификация, торг, закрытие, терминология. Раньше
набор зависел от целей сценария — сценариев нет, а работа диспетчера от звонка
к звонку не меняется.

`leftOnTable` — сколько брокер был готов доплатить сверх согласованного. Студент
узнаёт это только в разборе, и это самая полезная цифра во всём отчёте.

## Что где лежит

```
server/devProxy.ts     ключи, системный промпт, схемы инструментов, прокси вебсокета
src/call/              makeCall (набор звонка), CallMachine, guards (торг), scoring
src/voice/             транспорты, детектор речи, телефонный звук
src/data/              словари для генератора, мок FMCSA, рынок, термины
src/screens/           начало, набор номера, экран звонка, разбор
src/design/            токены и база стилей
```

## Известные ограничения

- **Silero VAD не подключён.** Границы речи ловит энергетический детектор с
  адаптацией под шум комнаты. Он покрыт тестами и работает без внешних ассетов,
  но на сложном фоне Silero был бы точнее. Интерфейс под замену готов.
- **Живой разговор голосом не прогнан целиком.** Проверено: сборка, типы, 162
  теста, поднятие вебсокета Gemini до `setupComplete` и весь путь до микрофона.
  Сам микрофон, перебивание и звук в трубке надо прогнать руками — во встроенном
  браузере захват звука запрещён.
- **Gemini на боевом сайте не работает** — вебсокет проксируется дев-сервером,
  PHP так не умеет. Там остаётся прежний путь.
- Прогресс в localStorage; Firestore и XP-система подключатся вместе с сайтом.
