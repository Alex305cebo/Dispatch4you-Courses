# Broker Call — передача работы

Записка для следующей сессии (и для человека). Состояние на 12 августа 2026.

---

## 1. Коротко: что это и где

Голосовой тренажёр звонка фрахт-брокеру. Студент — **диспетчер**, он звонит и
букает груз. Модель играет **брокера**: спрашивает MC-номер, тип трейлера, где
водитель, и давит ставку вниз.

- Код: `broker-call/` (React + Vite + TypeScript)
- Серверная часть на боевом: `api/broker-call.php` + сгенерированный
  `api/broker-config.php`
- Живёт на <https://dispatch4you.com/broker-call/>
- Рабочая ветка: **`claude/ai-broker-chat-investigation-tfm3gf`**
- **В `main` НЕ смержено.** На сайте сейчас предыдущая версия, без Gemini.

Старая страница `pages/ai-broker-chat.html` работает как работала — её не
трогали.

## 2. Что сделано в этой сессии

Переход разговора на **Gemini Live API** (вебсокет, звук потоком в обе стороны)
с сохранением всего прежнего как запасного пути.

| Файл | Что |
|---|---|
| `src/call/geminiTools.ts` | схемы инструментов OpenAI → Gemini |
| `src/call/geminiModels.ts` | выбор модели по политике, без имён в коде |
| `src/voice/geminiProtocol.ts` | разбор и сборка сообщений вебсокета |
| `src/voice/pcm.ts` | PCM16 ↔ Float32 ↔ base64 |
| `src/voice/geminiVoices.ts` | голоса Gemini |
| `src/voice/GeminiLiveTransport.ts` | сам транспорт |
| `server/devProxy.ts` | `/api/gemini-session`, `/api/health`, разбор через Gemini |
| `api/broker-call.php` | то же самое на боевом |
| `src/store/useCallStore.ts` | порядок транспортов и откат |

Плюс инфраструктура для работы в двух местах:

- `.claude/hooks/session-start.sh` — на старте сессии ставит зависимости и
  печатает: ветку, незакоммиченное, расхождение с GitHub, разошёлся ли
  сгенерированный конфиг со сборкой.
- `start-local.bat` (и `start-local.sh`) в корне — запуск на своей машине одним
  действием.

**155 тестов, типы и сборка — зелёные.**

## 3. Что НЕ проверено — читать обязательно

**Живого успешного звонка не было ни разу.** Ни на пайплайне, ни тем более на
Gemini. Всё, что проверено, — сборка, типы и тесты логики. Gemini-транспорт
никогда не разговаривал с настоящим API: в облачном контейнере нет ключей, а
`dispatch4you.com` заблокирован сетевой политикой среды (проверено: gateway
отвечает 403 на CONNECT).

Поэтому первое, что надо сделать локально, — **дойти до первого настоящего
разговора** и смотреть, где он сломается. Не писать новый код, пока этого не
случилось.

## 4. Что нужно от человека

### Ключ Gemini

1. <https://aistudio.google.com/apikey> → **Create API key** → скопировать
   (строка вида `AIza...`)
2. Для локальной работы: положить в `broker-call/.env.local` строкой
   ```
   GEMINI_API_KEY=AIza...
   ```
   Файл создастся сам при первом запуске `start-local.bat`.
3. Для боевого сайта: файл `gemini.key` на Hostinger в той папке, **внутри
   которой лежит `public_html`** — там же, где уже лежит `groq.key`. Путь
   зашит в коде: `api/groq.php:37` читает `__DIR__ . '/../../groq.key'`.

Пока файла нет — ничего не меняется: `config` отдаёт `gemini: false`, фронт даже
не пробует, звонок идёт прежним путём.

### Условия Groq (не срочно)

<https://console.groq.com/playground?model=canopylabs/orpheus-v1-english> —
открыть и принять условия модели. Сейчас Groq отвечает «terms acceptance», и
запасная озвучка молчит. Если Gemini заработает, это не нужно.

## 5. Как запускать локально

```
cd C:\DispatcherTraining
git checkout claude/ai-broker-chat-investigation-tfm3gf
git pull
```

Дальше двойной клик по `start-local.bat` в корне. Он сам: подтянет ветку,
поставит зависимости, заведёт `.env.local`, поднимет дев-сервер и откроет
браузер.

Вручную то же самое:

```
cd broker-call
npm install
npm run dev
```

Открывать **<http://localhost:5180/broker-call/>** — обязательно с `/broker-call/`
на конце, приложение живёт в подпапке.

Vite печатает второй адрес вида `http://192.168.x.x:5180/broker-call/` — по нему
тренажёр открывается **с телефона в той же Wi-Fi**. Микрофон и звук иначе не
проверить.

## 6. Если не работает — куда смотреть

Порядок ровно такой:

1. **<http://localhost:5180/api/health>** — живые пробы каждого сервиса тем же
   путём, каким идёт звонок, и текст отказа провайдера как есть. На боевом та же
   ручка: `https://dispatch4you.com/api/broker-call.php?action=health`.
2. **Консоль браузера (F12).** Если Gemini не поднялся, там будет строка
   ```
   [broker-call] транспорт gemini-live не поднялся, откат: <причина>
   ```
   Звонок при этом пойдёт по-старому — то есть «работает, но по-старому» тоже
   надо проверять по консоли, а не по ощущению.
3. **Красная полоса на экране звонка** — ошибки, видимые студенту.

## 7. Как это устроено — три вещи, которые надо понять до правок

**Транспорты взаимозаменяемы.** `VoiceTransport` (`src/voice/types.ts`) — один
интерфейс, три реализации: `GeminiLiveTransport`, `RealtimeTransport`,
`PipelineTransport`. Экран звонка и `CallMachine` не знают, кто работает.
Порядок попыток строит `buildCandidates` в `src/store/useCallStore.ts`: Gemini
(если сервер сказал, что есть ключ) → Realtime (если включён явно) → пайплайн
всегда последним. Не поднялся — тихо сворачивается (`abandon()`) и звонок идёт
следующим.

**Состояние звонка меняется только вызовами инструментов.** `CallMachine`. Ни
одной регулярки по транскрипту: в старой версии `locationAnswered` срабатывал на
слово «ready» в любом контексте, а `bookingDone` — на слово «george».

**Потолок ставки лежит в коде, а не в промпте.** `src/call/guards.ts`.
`propose_rate` возвращает решение, а не мнение. Тест гоняет десять раундов
торга и проверяет, что потолок не переступается. Раньше это была фраза в
промпте, и модель её нарушала.

## 8. Грабли, на которых уже горели

Каждая стоила отдельного разбирательства. Не наступать заново.

- **Имя модели, вписанное в код.** Горели трижды: Groq снял
  `llama-3.3-70b-versatile` с бесплатного тарифа, `playai-tts` объявили
  устаревшим, голоса Orpheus у Groq назывались не как в оригинальном Orpheus.
  Каждый раз всё замолкало разом, а причина была в чужом changelog. Поэтому
  имён моделей в коде нет: `src/call/geminiModels.ts` хранит политику, а имя
  приходит из `models.list` при запуске.
- **Пустой `properties: {}` в схеме инструмента.** Groq валидирует схемы строго
  и роняет **запрос целиком**, а не отключает один инструмент. Брокер молчал на
  всех моделях сразу. Отсюда тест `toolSchemas.test.ts`.
- **`max_tokens` у рассуждающих моделей.** `gpt-oss` его не принимают — весь
  запрос падает с 502. Лечится `shapePayload`.
- **Проба, которая проверяет не то, что ломается.** Прежний health слал голый
  ping без инструментов и светился зелёным, пока разговор падал. Теперь пробы
  идут тем же путём: тот же список моделей, та же подгонка тела, те же схемы.
- **`audioSession.type = 'playback'` на iOS.** Выглядит подходящим и мьют
  игнорирует, но **запрещает захват микрофона**. Нужно `play-and-record`.
  См. `src/voice/audioUnlock.ts`.
- **Разъезд TypeScript и PHP.** Промпты и схемы живут в TS и выгружаются в
  `api/broker-config.php`. Правка промпта без пересборки конфига уезжает на
  сервер молча: фронт новый, брокер по-старому. Пересобирать:
  ```
  cd broker-call && npm run build:server-config
  ```
  CI это теперь проверяет и падает при расхождении.
- **Роли путались в разборе.** Модель советовала студенту «спросить MC-номер» —
  это работа брокера, а не диспетчера. Починено в двух местах: блок
  `WHO DOES WHAT` в промптах и таблица `GOAL_WORDING`, переводящая кодовые
  имена целей (`give_mc`) в человеческие фразы. Таблица выгружается в
  `broker-config.php`, иначе на боевом починка работала бы наполовину.
- **cwd сбрасывается между командами.** Перед `npm`/`git` всегда явный `cd` в
  нужную папку, иначе vitest подхватывает тесты всего монорепо.

## 9. Что делать дальше — по порядку

1. Добыть ключ, положить в `.env.local`, запустить локально.
2. **Дойти до первого настоящего разговора.** Смотреть `/api/health` и консоль.
   Чинить то, что реально сломается, а не то, что кажется.
3. Проверить с телефона по адресу `192.168.x.x` — микрофон, перебивание, звук
   в трубке.
4. Только после этого — `gemini.key` на сервер и мерж в `main`.

## 10. Правила

- **В `main` не пушить без явной просьбы.** Мерж в main = деплой на живой сайт.
- Заканчивая работу — `git push`. Облачный контейнер одноразовый, незапушенное
  пропадает.
- Прежде чем править: убедиться, что ветка не отстала. Это печатает хук старта
  сессии.
